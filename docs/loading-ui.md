## Сборка при ограниченной памяти

Рабочий установщик читает современные бандлы UnityFS порциями по 128 КиБ.
Распакованные данные больших объектов и ресурсов не копятся целиком.
Существующие объекты UnityPy и правила локализации применяются как раньше.
Файл с изменениями пишется в соседний временный файл и становится доступен
установщику после завершения записи. Для готовых композитов внутри одного
бандла выделено 48 МиБ, остальные временно хранятся на диске в PNG без
потерь. Их пиксели, ориентация и альфа сверены с обработкой в памяти.

Количество потоков сжатия выбирается заново для каждого бандла по числу
логических процессоров, доступной физической памяти и доступному лимиту
выделения памяти в Windows. Диапазон от одного до восьми. Если параллельная
сборка упирается в память или не может создать поток, этот бандл собирается
повторно в одном потоке. Все режимы используют одинаковый LZ4 и выдают
одинаковые данные. Проверка уже установленных файлов и чтение ресурсов
оформления используют тот же порционный загрузчик. Для прочих форматов
остаётся штатный путь UnityPy. [Показатели памяти Windows](https://learn.microsoft.com/en-us/windows/win32/api/sysinfoapi/ns-sysinfoapi-memorystatusex)

Прогон на реальном `gk2_movie` в одном потоке с жёстким ограничением 320 МиБ
завершился за 20,5 секунды при пике выделенной памяти 112 МиБ. Старый загрузчик
UnityPy при том же ограничении получил `MemoryError`. Хэши 23 неизменённых
объектов совпали, оба перенаправления сверены. Обычный UnityPy прочитал
пересобранный бандл выкриков с 18 проверенными перенаправлениями.
В четырёх потоках `gk2_movie` собрался за 12,9 секунды с тем же SHA-256
(`90b9820a30d0…`).
На изолированной копии бандла выкриков проверены атомарная замена и откат
с восстановлением исходного SHA-256.

`gk2_mapbgclassic` собран при ограничении 384 МиБ с пиком 355 МиБ.
Полученный файл побайтно совпал с результатом до ограничения буфера
композитов. Сборка `gk2_mapbg` порционным кодом с двумя потоками заняла
45 секунд на том же ПК вместо 103 секунд в прежнем тесте. Новый результат
занял 590 МБ против 584 МБ. Этот замер сделан до ограничения буфера композитов.

Полный `--build-only` штатного набора прошёл с одним потоком сжатия и
ограничением процесса 640 МиБ после ограничения буфера композитов.
Во временной папке получен 41 файл, 3 542 943 812 байт. Время 479 секунд,
пик выделенной памяти 414 МиБ. Прогон не менял файлы игры. Упакованный EXE
и время полной установки на быстром ПК остаются к проверке.

Это проверка комплектности/формата, редакторскую вычитку она не заменяет.

Обычный запуск в Windows без аргументов открывает графическое окно. Кнопка
«Установить перевод» начинает прежний конвейер установки; до нажатия читаются
только ресурсы оформления. Если автопоиск не удался, доступен выбор папки игры.

Windows EXE проверяет выпуски GitHub при открытии и затем раз в час. Скачивание
начинается по кнопке «Обновить установщик». После проверки размера и SHA-256
открывается новый EXE, в котором можно запустить установку. При обычном запуске
исходный EXE открывает последнюю рабочую копию из кеша. В кеше остаётся и одна
предыдущая копия на случай, если основная не откроется. Проверка обновлений и
запуск из пользовательского кеша отключены при запуске от администратора.

Кнопка «Вернуть предыдущую версию перевода» появляется после установки новой
версии поверх прежней. Подтверждение показывает тег, если он был записан при
прошлой установке. Перед заменой установщик сохраняет прежние файлы игры,
включая изменившуюся графику, в `_backup_ru/versions`. Откат сверяет их хэши
и хэши текущих файлов. Если Steam заменил один из них, откат остановится до
записи. Для снимка нужно место под заменённые бандлы. При штатном откате
оригинальный бэкап `_backup_ru` сохраняется.

Фон — исходная `map00` из `gk2_mapbg_trial`, извлекается во временную папку и
затемняется для читаемости. Музыка — `BGM_04` из `gk2_bgm_trial` (резервный
бандл `gk2_bgm`), декодируется в память. Громкость PCM снижена до 35%; кнопка
выключает и включает музыку, системная громкость не меняется. На завершении
музыка останавливается. Без ресурса или аудиоустройства установка доступна.
Игровые картинки и музыка в EXE не включаются.

Пять полос: реплики, таблицы, совместимость GK1, шрифты, графика и звуки.
События `args.progress` поступают из рабочего потока через очередь, интерфейс
остаётся доступным. Счётчики показывают реально обработанные файлы/бандлы.
До появления точного знаменателя движется неопределённая полоса. Общая полоса
считает долю выполненных этапов с одинаковым весом, а не оставшееся время.
Заливка плавно приближается к измеренному значению, внутри движутся диагонали.

В шапке названия сцен динамически берутся из `gk_common_title` в данных перевода:
только три заголовка начала первого дела. В карточках этапов декоративные
заголовки убраны после замечания пользователя: они выглядели как статус проверки
только первой главы. Там теперь пояснения реальной работы каждого этапа.
Игровая сборка работает с целыми бандлами. Имена последующих глав не показываются.

Команды из корня репозитория:

```powershell
.venv\Scripts\python.exe patcher/aai2ru.py --gui
.venv\Scripts\python.exe patcher/aai2ru.py --preview
.venv\Scripts\python.exe patcher/aai2ru.py --console --no-pause
```

этих режимов с `--gui`/`--preview` отклоняется. Во время установки закрытие
окна блокируется, чтобы не оборвать запись файлов; окно можно свернуть.

Код: `patcher/loading_ui.py`, `loading_assets.py`, `loading_audio.py`, события
в `aai2ru.py` и `steps.py`. Сборщик автоматически включает три новых модуля по
замыканию импортов; Tk/Pillow подхватываются PyInstaller. Исправлено разрешение
путей данных при относительном `--out` (относительно spec оно давало неверный путь).
