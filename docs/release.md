## Что решено

1. **Две ветки.** `main` — витрина для игрока: продающий README, патчер и его
   исходники. `dev` — вся разработка: скрипты, документы, состояние перевода, скиллы.
   На GitHub веткой по умолчанию ставится `main`, чтобы гость попадал на витрину.
2. **Патч ставится на месте.** Патчер несёт только наш текст и пересобирает файлы
   игры на машине пользователя. Готовых игровых файлов не раздаём.
3. **В релиз идёт всё переведённое на сегодня** — все пять дел и общая механика,
   интерфейс и принятая графика текущего слоя. Оставшаяся графика показывается
   по-английски.
4. **Кадры и ролик снимает пользователь** по раскадровке из `press-kit.md`.

## Почему не «готовые файлы», хотя они уже работают

`tools/make_installer.py` + `install.ps1` собраны, проверены и ставят перевод на чужой
машине без Python. Как способ раздачи отвергнуты:

| | Готовые файлы | Патч на месте |
|---|---|---|
| Размер раздачи | 110 МБ, из них `data.unity3d` — 113 МБ одним файлом | наш текст, единицы МБ |
| GitHub | в ветку не кладётся: жёсткий лимит 100 МБ на файл, только Release | кладётся в ветку как есть |
| Чужое | раздаём файл Capcom целиком ради правки шрифта внутри | раздаём только свой текст |
| Обновление игры | имена бандлов содержат хеш сборки: после патча Steam релиз мёртв целиком | бандлы ищутся по префиксу |
| Графика | +2,9 ГБ к раздаче | бесплатно, правится файл пользователя |

Решающим был четвёртый пункт. `install.ps1` при несовпадении версии честно
отказывается ставить («версия игры не та»), и вылечить это со стороны раздачи нельзя —
только пересобирать релиз под каждое обновление игры. Патч на месте берёт бандл,
который лежит у пользователя, и потому переживает обновление, пока цел формат.

Сам `install.ps1` не выбрасывается: он остаётся способом поставить перевод на свою
вторую машину без Python и запасным вариантом, если пересборка у кого-то упадёт.

## Что делает патчер

Порядок шагов, каждый обратим:

1. **Найти игру** — сначала рядом с EXE патчера и в текущей папке, затем
   в библиотеках Steam из реестра и `libraryfolders.vdf`, наконец рекурсивно
   на подключённых локальных дисках Windows (включая USB, без сетевых дисков).
   Маркер — файл `GK12.exe` и каталог `GK12_Data`. Недоступные папки, ссылки
   и junction пропускаются; долгий поиск показывает прогресс. Ключ `--game-path`
   задаёт папку сразу и отключает автоматический поиск.
2. **Отказаться заранее**, если игра запущена (Unity держит хэндлы на бандлы),
   нет прав на запись или мало места на диске.
3. **Бэкап оригиналов** в `<игра>/_backup_ru` с манифестом sha256 — до первой записи.
4. **`data.unity3d`** — атлас, cmap и метрики шрифтов. Без этого шага кириллица
   не рисуется вообще: настоящий склад гарнитур лежит здесь, а не в бандлах
   ([`font-atlas.md`](font-atlas.md)).
5. **Два скриптовых бандла** — содержимое берётся из английских, поверх ложится наш
   перевод. Ровно то, что делает `build.py`, но на файлах пользователя.
6. **Две таблицы строк** — так же, `build_strings.py`.
7. **Графика** — немецким адресам отдаются английские объекты (`swap_localized.py`).
   Байты ассетов не трогаются, правится таблица «адрес → объект»; выключается ключом.
   **Русские надписи на картинках** (с 13 сентября 2026) приезжают слоем
   `data/graphics_layers/` — только наши пиксели — и склеиваются тут же из английской
   текстуры игрока (`picture_layer.py`). Английская картинка не та, по которой снят
   слой, — надпись остаётся английской. Перед выпуском слой собирает `make layers`,
   устаревший `publish_release.py` не возьмёт; проверка пути — `make selftest`.
8. **Перечитать записанное** и сверить — как `verify_build.py`.

Откат — `--uninstall` из `_backup_ru`. Бэкапа нет — Steam, «Проверить целостность
файлов игры»: перевод не переживёт проверку целостности, и это правильный аварийный люк.

## Откуда патчер берёт код

Источник истины — `tools/`. Патчер не форк, а **сборка**: `tools/publish_release.py`
складывает дерево ветки `main` из уже существующих модулей (`tps`, `segments`,
`carriers`, `bundle_io`, сборщики) плюс данные перевода, урезанные до нужных полей.
Дальше PyInstaller делает из этой же папки `.exe`.

Отсюда обещание витрины: **бинарник собран ровно из тех исходников, что лежат рядом
в ветке**. Кто боится чужого `.exe` — ставит Python, `pip install -r requirements.txt`
и запускает тот же код скриптом.

## Состав ветки `main`

```
README.md          витрина: что это, как поставить, кадры, ролик
LICENSE            MIT на код + оговорка о фанатском статусе и Capcom
patcher/           исходники патчера: то же, из чего собран .exe
  requirements.txt
  opcodes.json     таблица опкодов — данные разбора, не документация
  data/            текст перевода, урезанный до нужных полей
    graphics_layers/  слой русских надписей: изменённые пиксели и маски, без рисунка игры
press/             кадры и гифка для README
```

**`.exe` раздаётся через GitHub Releases, а не лежит в ветке — пересмотрено
17 августа 2026.** Прежнее решение (файл прямо в ветке, чтобы кнопка «Скачать»
работала без лишних кликов) стоило дорого: git не забывает блобы, и к 17 августа
две сборки заняли 46 МБ из 81 МБ `.git`. Каждая следующая добавляла бы ещё 23 МБ
навсегда.

Как теперь: `publish_release.py --exe` кладёт `.exe` в `dist/release/`,
`publish_branch.py` **не переносит его в ветку** (список `ASSETS`) и печатает
готовую команду `gh release create`. Ссылка в витрине ведёт на
`/releases/latest/download/AAI2-RU.exe` — она всегда указывает на свежий выпуск
и не зависит от номера версии, но **заработает только после того, как выпуск
с этим вложением создан**.

Две сборки, уже лежащие в истории `main`, так не убрать: ветка генерируемая,
и при желании её можно пересоздать заново одним orphan-коммитом — отдельным
решением, потому что это force-push поверх публичной ветки.

## Немецкого не должно остаться нигде

**Требование пользователя от 12 августа 2026.** Всё непереведённое обязано
показываться по-английски. Где немецкий мог бы просочиться и чем закрыт:

| Пласт | Чем закрыт |
|---|---|
| Реплики GK2 | `build.py` пишет в слот все 399 + 44 ассета английского бандла |
| Таблицы строк | `build_strings.plan()` берёт значение из английской таблицы, если русского нет |
| Название языка в меню | «Deutsch» → «Русский», две записи `gk_common_option` в `strings.json` |
| Таблицы строк GK1 | `plan()` идёт по всем английским таблицам, включая `gk1_*` |
| **Реплики GK1** | **было не закрыто**; шаг `steps.gk1_scripts` — 12 августа 2026 |
| Графика, ролики, выкрики GK2 | `swap_localized`, 33 бандла |
| Графика GK1 | ключ `--gk1-graphics`, по умолчанию выключен: +2,3 ГБ и пять минут |

Реплики первой игры оказались единственной настоящей дырой: в её немецком бандле
271 ассет, и совпадали с английским только три. Теперь содержимое берётся
из английского бандла сырыми байтами — формат GK1 разбирать не нужно.

## Замеры, на которые опирается витрина

Своя машина, игра на системном диске:

* текст целиком (реплики, таблицы, GK1, гарнитуры) — **41 секунда**;
* графика — **2,9 ГБ и около 7 минут**, скорость перезаписи ~7 МБ/с (2 октября 2026 на своей
  машине — 529 с);
* **повторная установка** (новая версия перевода поверх прежней) — графика **1 с**: бандлы,
  которые уже стоят и не менялись, пропускаются (`steps.graphics`, запись `graphics`
  в `_backup_ru/manifest.json`: отпечаток рецепта и отметка файла). Пересобираются только
  бандлы, где появились или изменились русские картинки, их бандлы-источники уменьшенных копий,
  и всё, что Steam обновил или вернул. Замер: один бандл с уменьшенной копией — он и источник,
  18 с. `GRAPHICS_VERSION` в `steps.py` поднимать, когда меняется код сборки графики, — иначе
  у игроков останутся бандлы прежней сборки. `--full` — всё заново, как раньше;
* самый крупный бандл — `gk2_mapbg`, 510 МБ, один держится в памяти целиком.

Отсюда решение по бэкапу: **графику не бэкапим по умолчанию**. Это ещё 2,9 ГБ
на диске, а откат для неё не нужен — английские надписи ничему не мешают,
и полное восстановление в один клик даёт Steam. Кому надо — `--backup-graphics`.
Текст и гарнитуры бэкапятся всегда, они весят 113 МБ.

## Как выпускать новую версию

Ветка `main` **генерируется**, править её руками нельзя. Из ветки `dev`,
при закрытой игре, две команды:

```bash
make release    # проверки, дерево витрины, AAI2-RU.exe
make publish    # перенос в ветку main и отправка
```

Счётчики в README подставляет `publish_release.py` из данных перевода,
а размер `.exe` — после его сборки. Витрина поэтому не может соврать о том,
сколько переведено.

С 20 октября 2026 прогресс картинок GK2 тоже собирается автоматически:
`graphics-progress.svg` и поля `gk2_pictures_*` в `version.json`. Знаменатель —
все локализуемые Texture2D GK2 из `work/localized_assets.json` и отдельный
список интерфейса GK2 в `work/graphics_ru/coverage.json`. HD и обычные версии
считаются отдельно. Явные исключения и картинки без текста вычитаются по этому
реестру с причинами; новый неразобранный ресурс остаётся долгом. Числитель —
только картинки в поставляемом слое, а не готовые PNG на своей машине.
Общие экраны запуска сборника, видео, звук и геометрия 3D в этот счёт не входят.
Проверка `tools/test_publish_progress.py` сторожит новые долги, неизвестные
интерфейсные ресурсы, исключения и соответствие SVG числам.

### Правка прямо в ветке — потеряется

12 августа 2026 пользователь поправил README через веб-интерфейс GitHub, и первая
же публикация стёрла бы правку молча: ветка заменяется целиком. Теперь `make publish`
такое **не пропускает** — свои коммиты `publish_branch.py` метит строкой в сообщении,
чужие показывает поимённо и останавливается.

Правильный порядок: правка идёт в **[`release/README.md`](../release/README.md)**,
дальше `make release && make publish`. Если правка уже перенесена руками —
`.venv/Scripts/python.exe tools/publish_branch.py --push --force`.

## Что осталось незакрытым

**Патчер не проверялся на настоящей чужой машине.** Подставная папка игры
доказала логику, но не доказала, что на компьютере без Python и без нашего
окружения `.exe` найдёт Steam в другом месте, переживёт другой антивирус
и другую кодовую страницу консоли. Это следующая проверка, и её место —
второй компьютер.

**Первая установка занимает около двенадцати минут**, из них пять — пересборка
семи гарнитур. Ускорить можно параллельным пересчётом (гарнитуры независимы),
но это отдельная работа с процессами внутри PyInstaller, и без замера на чужой
машине браться за неё рано.

## Открытые вопросы

- **Антивирус.** Собранный PyInstaller-ом `.exe` без подписи часто ловит
  ложное срабатывание SmartScreen. В README про это написано прямо, но проверить
  на чистой машине всё равно надо: если ругается не SmartScreen, а сам антивирус
  и файл удаляется, одной честной строчкой не обойтись.
- **Двенадцать минут установки.** Пять из них — пересборка гарнитур, и они
  независимы, то есть параллелятся. Браться до замера на чужой машине рано.

Закрыто: имя `AAI2-RU.exe` (кириллица в имени ломается на чужих кодировках),
лицензия MIT на код с отдельной оговоркой про текст перевода, графика GK1 —
ключом по умолчанию выключенным.
