# Инструменты: что чем делается

> Справочник по всем скриптам в `tools/`. Сюда — когда непонятно, чем сделать задачу
> или что делает попавшийся на глаза скрипт. Порядок работы — [`workflow.md`](workflow.md),
> состояние проекта — [`STATE.md`](STATE.md).
>
> **Дописывать сюда сразу**, как только в `tools/` появляется новый скрипт.

Всё запускается как `.venv\Scripts\python.exe tools\<имя>.py`.

**Вывод гнать через `PYTHONIOENCODING=utf-8`**, иначе кириллица падает с
`UnicodeEncodeError`: консоль по умолчанию cp1251. Особенно если перенаправляете
вывод в файл — там ломается молча.

```bash
PYTHONIOENCODING=utf-8 .venv/Scripts/python.exe tools/who.py sce1_c0_06 --todo
```

## Два независимых конвейера

Текст игры лежит в двух разных местах, и это не одно и то же хранилище.

| | Реплики | Строковые таблицы |
|---|---|---|
| **Что там** | Сюжетные диалоги, осмотр улик, логика | Имена в плашке, названия и описания улик, профили, интерфейс |
| **Где** | Бандл `gk2_scriptmessage_ger`, формат ` TPS` | Бандлы `localization-string-tables-german(de)`, MonoBehaviour с typetree |
| **Рабочий файл** | `work/case2.json` | `work/strings.json` |
| **Извлечь** | `extract.py` | `extract_strings.py` |
| **Влить пачку** | `apply.py` | правка файла |
| **Проверить** | `check_len.py` | `check_strings.py` |
| **Собрать** | `build.py` | `build_strings.py` |
| **Проверить сборку** | `verify_build.py` | встроена в `build_strings.py` |

Профили персонажей отдельной таблицы не имеют — они лежат в тех же `gk2_item_name`
и `gk2_item_text`, что и улики.

## Конвейер реплик

### `extract.py`
Вытаскивает реплики дела 2 из английского бандла в `work/case2.json` — 7402 сегмента
в 74 файлах. Единица перевода — сегмент блока, адрес вида
`sce1_c0_01.bytes|01000080|6`. **Перезапускать безопасно:** уже сделанный перевод
переносится, если английский оригинал сегмента не изменился.

### `who.py`
Показывает, **кто говорит** в каждом сегменте, вместе с текстом и готовым переводом.
Без него нельзя применить [`voices.md`](voices.md): имени говорящего в самом тексте
реплики нет, оно закодировано параметром кода `E101` в преамбуле.

```bash
PYTHONIOENCODING=utf-8 .venv/Scripts/python.exe tools/who.py sce1_c0_06 --todo
```

Аргумент — имя файла или его начало, поэтому `sce1_c0_` возьмёт всю главу.
`--todo` оставляет только непереведённое. Таблица «кто есть кто» — в самом скрипте,
она собрана из [`voices.md`](voices.md).

Не путать со `speakers.py`: тот решает обратную задачу — группирует реплики по
персонажу, чтобы **составить** профиль речи.

### `apply.py`
Вливает пачку переводов в `work/case2.json` из отдельного файла-патча. Правка
семитысячного JSON руками ненадёжна: одна съехавшая запятая — и потерян весь файл.

```bash
PYTHONIOENCODING=utf-8 .venv/Scripts/python.exe tools/apply.py work/patch.json
```

Патч — JSON вида `{"sce1_c1_07.bytes|01000D00|3": "перевод", ...}`; принимается
и список записей `[{"id": ..., "ru": ...}]`. Применение идемпотентно.

Незнакомый идентификатор — ошибка, **ничего не пишется**: почти всегда это опечатка
в номере сегмента. Перезапись уже переведённого требует `--force`, иначе повторный
прогон старого патча тихо откатил бы правки редактуры. `--dry-run` — только отчёт.

### `check_len.py`
Проверяет `work/case2.json`: сохранность управляющих кодов, наличие кириллицы,
геометрию окна. `--all` добавляет сводку по длинам строк.

Гонять **с `--all` и добиваться `длиннее 50: 0`.** Жёсткий предел 53 проверка
пропускает, но 50 — то, что реально выдержали французы и немцы; всё сверх этого
рискует не поместиться в окно.

Две неочевидные вещи, которые он умеет и которые стоили отладки (разбор —
в [`limits.md`](limits.md)):

* **Две строки — лимит окна, а не сегмента.** Коды `E104` и `E106` закрывают окно,
  после них счёт строк начинается заново.
* **Режим окна меняется по ходу реплики** кодом `E107`, поэтому узкий лимит
  в 24 символа применяется только к строкам, которые реально дорисовываются
  в узком окне.

### `build.py`
Собирает бандл реплик. Содержимое берётся из **английского** бандла, перевод кладётся
поверх, результат пишется в слот-носитель (немецкий). Переписываются все 399 ассетов:
всё непереведённое уезжает в игру английским, а не немецким.

```bash
.venv\Scripts\python.exe tools\build.py            # черновая сборка в work/build/
.venv\Scripts\python.exe tools\build.py --install  # установка, ИГРА ДОЛЖНА БЫТЬ ЗАКРЫТА
```

### `verify_build.py`
Последний рубеж перед установкой: смотрит не на JSON, а на то, что реально вышло
внутри бандла. Сверяет с английским эталоном, ругается на оставшийся немецкий,
проверяет round-trip, кириллицу, сохранность кодов и то, что все 16 «сломанных» букв
уехали кодами-носителей.

## Конвейер строковых таблиц

### `extract_strings.py`
Вытаскивает таблицы в `work/strings.json` — 2823 записи в 18 таблицах. Рядом
с английским значением кладётся **немецкое, для справки**: немцы решали ровно те же
задачи, и подсмотреть бывает полезно (Knight у них Springer, то есть шахматный конь).
Таблицы первой игры пропускаются — она вне объёма.

### `check_strings.py`
Проверяет `work/strings.json`: кириллица, сохранность тегов `<font>`, геометрия.

Лимиты **не зашиты числами, а замеряются по самой игре** — по английским и немецким
значениям той же таблицы. Иначе никак: у каждой таблицы своё окно, и описание улики
это не реплика. `--all` показывает замеренное:

| Таблица | Строк | Символов |
|---|---|---|
| `gk2_common_nametag` | 1 | 21 |
| `gk2_item_name` | 1 | 31 |
| `gk2_item_text` | 5 | 50 |
| `gk2_logic_text` | 4 | 39 |
| `gk2_select_long` | 1 | 40 |

### `build_strings.py`
Собирает бандлы таблиц по тому же принципу, что `build.py`: содержимое английское,
русский поверх. Проверка встроена — скрипт перечитывает собранный бандл и
раскодирует носители обратно, сверяя с тем, что заказывали.

## Шрифты — ставятся один раз, не каждую итерацию

Разбор целиком — [`font-atlas.md`](font-atlas.md).

| Скрипт | Что делает |
|---|---|
| `patch_font_cmap.py` | Раздаёт кириллице коды-носители в обход письменности Борджинии |
| `patch_font_metrics.py` | Делает кириллицу пропорциональной, иначе текст идёт вразрядку |
| `carriers.py` | Таблицы «буква → код-носитель» и кодирование в обе стороны |
| `find_fonts.py` | Проверка гарнитур на наличие кириллицы |
| `font_ident_probe.py` | Опознаёт гарнитуру любого элемента интерфейса за один запуск |
| `patch_font_atlas.py` | Размер страницы атласа TMP |
| `alphabet_probe.py` | Диагностические билды: `basic`, `split`, `carriers`, `ident` |
| `patch_borginian.py` | **Отвергнут.** Памятка о том, почему коды освобождать нельзя |
| `find_borginian.py` | Сколько борджинийского текста в скриптах GK1 — что ломает освобождение |

## Разбор формата и диагностика

| Скрипт | Что делает |
|---|---|
| `tps.py` | Парсер формата ` TPS`, токенизация, разметка кодов. Модуль, не запускается |
| `segments.py` | Деление блока на сегменты — единицы перевода. Модуль |
| `bundle_io.py` | Чтение и запись ассетов Unity-бандла, включая typetree таблиц. Модуль |
| `common.py` | Пути, имена бандлов, слот-носитель `HOST`. Модуль |
| `speakers.py` | Группировка реплик по говорящему — для составления [`voices.md`](voices.md) |
| `measure_limits.py` | Замер ограничений окна по всем локализациям |
| `derive_opcodes.py` | Пересобрать таблицу параметров управляющих кодов |

## Установка и откат

| Скрипт | Что делает |
|---|---|
| `backup.py` | Бэкап оригиналов в `backup/` + `manifest.json` с SHA-256; `--verify` — проверить целостность |
| `restore.py` | Вернуть игру к оригиналу; `--check` — показать, что изменено |

Изменённых файлов должно быть четыре: шрифт `data.unity3d`, бандл реплик и два
бандла строковых таблиц. Список — в [`STATE.md`](STATE.md).
