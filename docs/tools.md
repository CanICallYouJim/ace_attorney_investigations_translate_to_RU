# Инструменты: что чем делается

> Справочник по всем скриптам в `tools/`. Сюда — когда непонятно, чем сделать задачу
> или что делает попавшийся на глаза скрипт. Порядок работы — [`workflow.md`](workflow.md),
> состояние проекта — [`STATE.md`](STATE.md).
>
> **Дописывать сюда сразу**, как только в `tools/` появляется новый скрипт.

Всё запускается как `.venv\Scripts\python.exe tools\<имя>.py`.

**Вывод гнать через `PYTHONIOENCODING=utf-8`**, иначе кириллица падает с
`UnicodeEncodeError`: консоль по умолчанию cp1251. Особенно если перенаправляете
вывод в файл — там ломается молча.

```bash
PYTHONIOENCODING=utf-8 .venv/Scripts/python.exe tools/who.py sce1_c0_06 --todo
```

## Ходовое — через `make`

Рутина собрана в [`Makefile`](../Makefile): он сам подставляет питон из venv
и `PYTHONIOENCODING`, так что забыть их нельзя. Список целей — просто `make`.
Запускать из Git Bash.

```bash
make check      # быстрые проверки              make patch       # накатить патчером
make build      # собрать, игру не трогать      make release     # витрина и AAI2-RU.exe
make install    # собрать и поставить в игру    make publish     # витрину в ветку main
make status     # что стоит в игре              make clean       # убрать собранное
```

`install` и `release` зависят от `check`: проверки гоняются сами, а не «когда
вспомнишь». Ниже — тот же набор поштучно, с разбором каждого скрипта.

## Два независимых конвейера

Текст игры лежит в двух разных местах, и это не одно и то же хранилище.

| | Реплики | Строковые таблицы |
|---|---|---|
| **Что там** | Сюжетные диалоги, осмотр улик, логика | Имена в плашке, названия и описания улик, профили, интерфейс |
| **Где** | Бандл `gk2_scriptmessage_ger`, формат ` TPS` | Бандлы `localization-string-tables-german(de)`, MonoBehaviour с typetree |
| **Рабочий файл** | `work/case2.json` | `work/strings.json` |
| **Извлечь** | `extract.py` | `extract_strings.py` |
| **Влить пачку** | `apply.py` | `apply_strings.py` |
| **Проверить** | `check_len.py` | `check_strings.py` |
| **Собрать** | `build.py` | `build_strings.py` |
| **Проверить сборку** | `verify_build.py` | встроена в `build_strings.py` |

Профили персонажей отдельной таблицы не имеют — они лежат в тех же `gk2_item_name`
и `gk2_item_text`, что и улики.

## Конвейер реплик

### `extract.py`
Вытаскивает реплики дела 2 из английского бандла в `work/case2.json` — 7402 сегмента
в 74 файлах. Единица перевода — сегмент блока, адрес вида
`sce1_c0_01.bytes|01000080|6`. **Перезапускать безопасно:** уже сделанный перевод
переносится, если английский оригинал сегмента не изменился.

### `who.py`
Показывает, **кто говорит** в каждом сегменте, вместе с текстом и готовым переводом.
Без него нельзя применить [`voices.md`](voices.md): имени говорящего в самом тексте
реплики нет, оно закодировано параметром кода `E101` в преамбуле.

```bash
PYTHONIOENCODING=utf-8 .venv/Scripts/python.exe tools/who.py sce1_c0_06 --todo
```

Аргумент — имя файла или его начало, поэтому `sce1_c0_` возьмёт всю главу.
`--todo` оставляет только непереведённое. Таблица «кто есть кто» — в самом скрипте,
она собрана из [`voices.md`](voices.md).

Не путать со `speakers.py`: тот решает обратную задачу — группирует реплики по
персонажу, чтобы **составить** профиль речи.

### `reread.py`
Выкладывает **переведённые реплики одного персонажа подряд** — для редакторской
вычитки. `who.py` даёт файл, всех вперемешку: так переводят. Здесь наоборот, один
герой сквозь всё дело, вне сцен: регистр речи съезжает незаметно, внутри своей сцены
каждая реплика выглядит уместной, и только полсотни подряд показывают дрейф.

```bash
PYTHONIOENCODING=utf-8 .venv/Scripts/python.exe tools/reread.py              # у кого сколько переведено
PYTHONIOENCODING=utf-8 .venv/Scripts/python.exe tools/reread.py --id 0000 --ru-only
```

`--ru-only` убирает английский: рядом с оригиналом проверяешь точность, а слышать
надо русский. `--file sce1_c1` режет участком, `--grep` фильтрует по переводу —
так проверяются решения из [`decisions.md`](decisions.md), например `--grep "\bты\b"`
у Эджворта. Говорящий переносится на следующие сегменты, поэтому реплик выходит
больше, чем в сводке `speakers.py`, — тот считает только явные объявления `E101`.

`--latin` работает **без `--id`**: это не вычитка персонажа, а прочёс участка на
латиницу, оставшуюся в русской реплике. Ищет в видимом тексте, а не в сыром —
в управляющих кодах вида `{E108:0010}` латиница есть всегда.

```bash
PYTHONIOENCODING=utf-8 .venv/Scripts/python.exe tools/reread.py --case all --latin --ru-only
```

Проверкой это быть не может: на 12 августа 2026 таких мест 30, и все законные —
французские вставки в речи двух героев, латинские видовые названия, коды дел.
Разделение сортов и что с каждым делать — скилл `/qa`.

Процедура вычитки целиком — скилл `/proofread`.

### `find_idioms.py`
Ищет **в английском оригинале устойчивые обороты** — места, где вероятна калька.
Отдельный инструмент понадобился потому, что прогон на книжную лексику этот класс
не видит вовсе: в кальке нет редких русских слов, она вся из обычных. «Хорошо было,
пока длилось» — четыре обычных слова и всё равно не по-русски. Признак только
с английской стороны: оборот, не равный сумме частей.

```bash
PYTHONIOENCODING=utf-8 .venv/Scripts/python.exe tools/find_idioms.py --counts
PYTHONIOENCODING=utf-8 .venv/Scripts/python.exe tools/find_idioms.py --case 3
```

`--counts` даёт сводку по оборотам, `--only` показывает один, `--untranslated`
добавляет ещё не переведённое. Список оборотов в самом скрипте **неполон
по устройству** — это сито, а не доказательство; пополнять при каждой новой
пойманной кальке. Прогон по делу 2 (11 августа): 60 сегментов, разбор —
[`../work/calques-2026-08-11.md`](../work/calques-2026-08-11.md).

**`--calques` — уже не сито, а тест.** Сито показывает английскую сторону и молчит
о переводе; словарь `CALQUES` держит **пару** «английский оборот → русская
дословщина, которую уже ловили» и валится на совпадении обеих сторон:

```bash
PYTHONIOENCODING=utf-8 .venv/Scripts/python.exe tools/find_idioms.py --calques --case all
PYTHONIOENCODING=utf-8 .venv/Scripts/python.exe tools/find_idioms.py --list
```

Ложных срабатываний почти нет именно из-за пары: «контора» сама по себе законна,
«контора» напротив `firm` — брак, разобранный пользователем. Намеренный оборот
не отключает проверку, а получает адресную строку в `ALLOWED` вместе с причиной —
там сейчас одна запись, «полноте» у судьи Молотовой.

Первый же прогон 12 августа 2026 нашёл **7 переживших** правку 11 августа: те же
кальки в других сегментах. Отсюда правило: пойманная вручную калька обязана стать
строкой словаря, иначе поймана одна реплика, а не класс.

### `test_polyglot_index.py`
Сторож правила №3: сверяет, что адрес `файл|БЛОК|индекс` означает в `polyglot.py`
ту же реплику, что в `work/caseN.json`. 11 августа выяснилось, что не означал —
два независимых бага адресации, оба тихие. Гонять после любой правки разбора
сегментов; сейчас 14600 адресов, 0 расхождений.

### `polyglot.py`
Показывает **один и тот же сегмент во всех семи локализациях игры**. Первое, что
делать с непонятным словом, каламбуром или выдуманным названием: посмотреть, как
с ним поступили официальные переводчики, и только потом изобретать своё.

```bash
PYTHONIOENCODING=utf-8 .venv/Scripts/python.exe tools/polyglot.py "sce1_c2_08.bytes|010021E6|18"
PYTHONIOENCODING=utf-8 .venv/Scripts/python.exe tools/polyglot.py --find "Li'l Vee"
PYTHONIOENCODING=utf-8 .venv/Scripts/python.exe tools/polyglot.py --block sce1_c2_08.bytes 010021E6
```

Две вещи, из-за которых он поначалу врал и которые уже учтены внутри:

* **немецкий читается из `backup/`.** В живой игре этот слот занят нашим переводом,
  а непереведённое в нём английское — колонка «немецкий» показывала бы английский текст;
* **`label_id` не уникален** (см. [`bytes-format.md`](bytes-format.md)): первый блок
  с нужной меткой бывает пустой склейкой из кодов. Берётся первый, где текст есть.

Разбивка блока на сегменты может разойтись между языками — где англичане уместили
фразу в одну реплику, немцы разбили на две. Тогда скрипт предупреждает и печатает
блок целиком.

Как читать вывод — в [`workflow.md`](workflow.md), раздел про непонятные места.

### `apply.py`
Вливает пачку переводов в `work/case2.json` из отдельного файла-патча. Правка
семитысячного JSON руками ненадёжна: одна съехавшая запятая — и потерян весь файл.

```bash
PYTHONIOENCODING=utf-8 .venv/Scripts/python.exe tools/apply.py work/patch.json
```

Патч — JSON вида `{"sce1_c1_07.bytes|01000D00|3": "перевод", ...}`; принимается
и список записей `[{"id": ..., "ru": ...}]`. Применение идемпотентно.

Незнакомый идентификатор — ошибка, **ничего не пишется**: почти всегда это опечатка
в номере сегмента. Перезапись уже переведённого требует `--force`, иначе повторный
прогон старого патча тихо откатил бы правки редактуры. `--dry-run` — только отчёт.

### `check_len.py`
Проверяет `work/case2.json`: сохранность управляющих кодов, наличие кириллицы,
геометрию окна. `--all` добавляет сводку по длинам строк.

Гонять **с `--all` и добиваться `длиннее 50: 0`.** Жёсткий предел 53 проверка
пропускает, но 50 — то, что реально выдержали французы и немцы; всё сверх этого
рискует не поместиться в окно.

Две неочевидные вещи, которые он умеет и которые стоили отладки (разбор —
в [`limits.md`](limits.md)):

* **Две строки — лимит окна, а не сегмента.** Коды `E104` и `E106` закрывают окно,
  после них счёт строк начинается заново.
* **Режим окна меняется по ходу реплики** кодом `E107`, поэтому узкий лимит
  в 24 символа применяется только к строкам, которые реально дорисовываются
  в узком окне.

### `build.py`
Собирает бандл реплик. Содержимое берётся из **английского** бандла, перевод кладётся
поверх, результат пишется в слот-носитель (немецкий). Переписываются все 399 ассетов:
всё непереведённое уезжает в игру английским, а не немецким.

```bash
.venv\Scripts\python.exe tools\build.py            # черновая сборка в work/build/
.venv\Scripts\python.exe tools\build.py --install  # установка, ИГРА ДОЛЖНА БЫТЬ ЗАКРЫТА
```

### `verify_build.py`
Последний рубеж перед установкой: смотрит не на JSON, а на то, что реально вышло
внутри бандла. Сверяет с английским эталоном, ругается на оставшийся немецкий,
проверяет round-trip, кириллицу, сохранность кодов и то, что все 16 «сломанных» букв
уехали кодами-носителей.

## Конвейер строковых таблиц

### `extract_strings.py`
Вытаскивает таблицы в `work/strings.json` — 2823 записи в 18 таблицах. Рядом
с английским значением кладётся **немецкое, для справки**: немцы решали ровно те же
задачи, и подсмотреть бывает полезно (Knight у них Springer, то есть шахматный конь).
Таблицы первой игры пропускаются — она вне объёма.

### `apply_strings.py`
Вливает пачку переводов в `work/strings.json`. Парный к `apply.py`, причина та же:
2823 записи руками не правятся, а патч лежит отдельным файлом и переживает обрыв сессии.

```bash
PYTHONIOENCODING=utf-8 .venv/Scripts/python.exe tools/apply_strings.py work/patch_ui.json
```

Патч — JSON вида `{"gk_common_button|38870646787": "Осмотреть"}` либо вложенный,
по таблицам: `{"gk_common_button": {"38870646787": "Осмотреть"}}`. Незнакомый ключ —
ошибка, ничего не пишется. `--force` разрешает перезапись, `--dry-run` — только отчёт.

**Идентификаторы числовые и длинные**, промахнуться легко, поэтому патч удобнее
не писать руками, а собирать по английскому тексту: в таблицах полно записей-дублей
(одна строка на PS4, Switch и PC), и перевод им нужен одинаковый.

### `check_strings.py`
Проверяет `work/strings.json`: кириллица, сохранность тегов `<font>` и остальной
разметки TMP, подстановки `{0}`, геометрия.

Лимиты **не зашиты числами, а замеряются по самой игре** — по английским и немецким
значениям той же таблицы. Иначе никак: у каждой таблицы своё окно, и описание улики
это не реплика. **Длина считается без разметки:** `<font="FOT-MODEMINALARGEPRO-B SDF"
material="...">Настройки</font>` это девять символов на экране, а не 96.
`--all` показывает замеренное:

| Таблица | Строк | Символов |
|---|---|---|
| `gk2_common_nametag` | 1 | 21 |
| `gk2_item_name` | 1 | 31 |
| `gk2_item_text` | 5 | 50 |
| `gk2_logic_text` | 4 | 39 |
| `gk2_select_long` | 1 | 40 |
| `gk_common_title` | 3 | 65 |
| `gk_common_option` | 8 | 93 |

Замеренный максимум таблицы — верхняя граница, а не разрешение: в `gk_common_title`
она берётся из описания стиля графики, тогда как **список глав в английском не
превышает 53 символов**, и длиннее его лучше не делать.

### `build_strings.py`
Собирает бандлы таблиц по тому же принципу, что `build.py`: содержимое английское,
русский поверх. Проверка встроена — скрипт перечитывает собранный бандл и
раскодирует носители обратно, сверяя с тем, что заказывали.

### `table_keys.py`
Отвечает на вопрос «эта запись таблицы — какого дела», и отвечает **данными игры,
а не догадкой по кластерам `m_Id`**. У каждой таблицы есть парный `SharedTableData`
в бандлах `localization-assets-shared*`, и там на каждый `m_Id` записан ключ:
`gk2_itm01_00c_00`, `gk2_topic04_030`, `gk2_cast205_01`. Номер в ключе — номер дела
с нуля, то есть `01` = дело 2.

```bash
PYTHONIOENCODING=utf-8 .venv/Scripts/python.exe tools/table_keys.py            # сводка
PYTHONIOENCODING=utf-8 .venv/Scripts/python.exe tools/table_keys.py --case 2 --todo
PYTHONIOENCODING=utf-8 .venv/Scripts/python.exe tools/table_keys.py --dump     # work/table_keys.json
```

Два ограничения, оба важные:

* **профили персонажей делом не размечены** — ключ `gk2_castNNN_MM` несёт номер
  персонажа и версию профиля, а не дело; версии разбираются по тексту;
* **набор дела ≠ то, что игрок в этом деле увидит.** Интерфейс «Малого вора»
  (`gk2_topic04_02f..031`) лежит в наборе дела 5, а показывается и в деле 2:
  копия строки в игре одна. Ключ говорит, где строка объявлена.

## Графика, ролики и звук — третий пласт языка

Надписи, запечённые в картинки, префабы, 3D-модели, ролики и выкрики. Слот-носитель
показывает их по-немецки. Разбор целиком — [`localized-assets.md`](localized-assets.md).

| Скрипт | Что делает |
|---|---|
| `scan_localized.py` | Перепись всех языковых ассетов игры в `work/localized_assets.json` |
| `export_localized.py` | Выгрузить картинки в PNG, `--sheet` — контактные листы, `--full` — в оригинальном разрешении |
| `swap_localized.py` | Отдать немецким адресам английские объекты; `--install` — в игру, `--check` — что стоит |
| `inject_localized.py` | Вставить свои PNG на место немецких — если надпись хочется по-русски |

Подмена пикселей не трогает: она идёт правкой таблицы «адрес → объект» внутри
бандла (`AssetBundle.m_Container`), а для локальной таблицы картинок — заменой GUID
в `Image Table_de`. Пиксели пишет только `inject_localized.py`, и в том же формате,
что был у оригинала: BC7 умеет `etcpak`, зависимость UnityPy, отдельный упаковщик
не нужен. `--raw` кладёт несжатым — вчетверо тяжелее, зато мгновенно.

`--check` гоняет по живым файлам игры и читает бандлы целиком, поэтому берите
категории по надобности: `--check gk1` — это полтора гигабайта на один бандл.
Буквенные заставки `inject_localized.py` **не берёт**: их куски лежат в спрайтовых
атласах, которых нет в контейнере, разбор — в [`localized-assets.md`](localized-assets.md).

```bash
.venv\Scripts\python.exe tools\swap_localized.py                            # план
.venv\Scripts\python.exe tools\swap_localized.py --build ui graphics movie --install
```

## Шрифты — ставятся один раз, не каждую итерацию

Разбор целиком — [`font-atlas.md`](font-atlas.md).

| Скрипт | Что делает |
|---|---|
| `patch_font_cmap.py` | Раздаёт кириллице коды-носители в обход письменности Борджинии |
| `patch_font_metrics.py` | Делает кириллицу пропорциональной, иначе текст идёт вразрядку |
| `carriers.py` | Таблицы «буква → код-носитель» и кодирование в обе стороны |
| `find_fonts.py` | Проверка гарнитур на наличие кириллицы |

## Установка и откат

| Скрипт | Что делает |
|---|---|
| `backup.py` | Бэкап оригиналов в `backup/` + `manifest.json` с SHA-256; `--verify` — проверить целостность |
| `restore.py` | Вернуть игру к оригиналу; `--check` — показать, что изменено |
| `make_installer.py` | Собрать переносимый комплект для чужого компьютера в `dist/` |

### `make_installer.py`

Складывает в `dist/AAI2-RU/` изменённые файлы игры и установщик к ним —
`install.bat`, `install.ps1`, `README.txt`, `files.json` с контрольными суммами.
Шаблоны установщика лежат в `tools/installer/` и правятся там, а не в `dist/`.

```bash
.venv\Scripts\python.exe tools\make_installer.py             # текст, ~110 МБ
.venv\Scripts\python.exe tools\make_installer.py --graphics  # плюс графика, 3 ГБ
.venv\Scripts\python.exe tools\make_installer.py --dry-run   # только состав
```

**Комплект делится на две части, и это не прихоть.** Текстовая (шрифт `data.unity3d`,
бандл реплик, две таблицы строк) весит 110 МБ, без неё перевода нет вообще: без
правленого шрифта кириллица не рисуется. Графическая — 35 бандлов на 2,9 ГБ, где
немецкие картинки, ролики и выкрики заменены английскими; без неё текст русский,
а «Einspruch!» и заставки остаются немецкими.

**Почему возятся готовые файлы, а не правки на месте.** Правку шрифтов и подмену
графики делает UnityPy — тащить его на чужую машину значит тащить туда Python
с пакетами, а установщик обязан работать сам по себе. Байтовая дельта тоже
отпадает: UnityPy пересобирает бандл целиком, и размер меняется — `data.unity3d`
худеет на 15 МБ, `gk2_mapbg` толстеет на 1,2 МБ.

**Установщик написан на PowerShell**, он есть в любой Windows. `install.bat` —
обёртка на двойной клик, она же обходит запрет на запуск `.ps1`.
Скрипт находит игру сам: реестр Steam (`HKCU\Software\Valve\Steam`, обе ветки
`HKLM`) плюс все библиотеки из `libraryfolders.vdf` — Steam ставит игры и на
другие диски. Не нашёл — принимает `-GamePath`.

Перед записью: игра закрыта, папка доступна на запись, места хватает, и **каждый
файл опознан по SHA-256** — оригинал, наш перевод или чужая правка. Отсюда три
внятные ошибки вместо порчи установки: «версия игры не та» (файла с таким именем
нет — имена бандлов содержат хеш сборки), «файлы уже кем-то изменены» (обходится
`-Force`), «нет прав на запись».

Оригиналы уходят в `_backup_ru` внутри папки игры, откат — `install.bat -Uninstall`.
Бэкапится только настоящий оригинал: иначе повторная установка сохранила бы
поверх него чужую правку.

Проверено на песочнице с оригиналами из `backup/`, все шесть веток:
установка, повторный запуск, откат, повторный откат, чужая правка, чужая версия.

Два места, где PowerShell ловит на ровном месте, — в скрипте они обойдены,
не возвращать обратно:

* `Copy-Item`/`Remove-Item` спотыкаются о пути с квадратными скобками и короткими
  именами вида `75BD~1`, поэтому файлы копирует `[System.IO.File]::Copy`;
* `.ps1` без BOM PowerShell 5.1 читает как cp1251, и кириллица в сообщениях
  превращается в мусор. Шаблон лежит в UTF-8 **с BOM**, а `.bat` — наоборот,
  без BOM: иначе `cmd` подавится первой строкой.

Изменённых файлов должно быть 37: шрифт `data.unity3d`, бандл реплик, два бандла
строковых таблиц и 33 бандла с графикой и звуком (ключи `asset_*` в манифесте;
их заносит `swap_localized.py --install`). В выводе `--check` строк 39: у двух
бандлов `gk_common_ingameui` по две записи, `font_*` и `asset_*`, на один и тот же
оригинал. Список — в [`STATE.md`](STATE.md).

Гонять после любых правок разбора формата.

| Скрипт | Что проверяет |
|---|---|

| `test_tokens.py` | 8,4 млн символов: параметры кодов не утекают в текст |
| `test_segments.py` | 259 901 сегмент: склейка совпадает с блоком, текст весь в теле |

`test_polyglot_index.py` 12 августа 2026 расширен на **оба** английских бандла
и на все дела из `common.CASES`, включая псевдодело 0. До этого он читал только
главный бандл и знал дела 2 и 3 списком — то есть на файлы общей механики
(`exam`, `logic_common`, `game_over`) не смотрел вовсе. В тот же прогон он поймал
неверную поправку таблицы опкодов, съедавшую по восемь букв с начала реплики.

### `check_all.py`
Гоняет **всё разом** и возвращает один код. Нужен потому, что проверок много,
запускаются они по одной руками — а значит, часть не запускается вовсе. Три дыры,
найденные 12 августа 2026, жили в игре месяц, и каждая была бы видна тому, кто
прогнал `audit_text.py`.

```bash
PYTHONIOENCODING=utf-8 .venv/Scripts/python.exe tools/check_all.py           # секунды
PYTHONIOENCODING=utf-8 .venv/Scripts/python.exe tools/check_all.py --full    # + бандлы игры
PYTHONIOENCODING=utf-8 .venv/Scripts/python.exe tools/check_all.py --build   # + собранный бандл
```

| Набор | Что входит | Когда |
|---|---|---|
| быстрый | `check_len`, `check_strings`, `find_idioms --calques` | каждая итерация перевода, до коммита |
| `--full` | + `test_tps`, `test_tokens`, `test_segments`, `test_polyglot_index` | перед сборкой в игру |
| `--build` | + `verify_build` | после `build.py`, до `--install` |

Упавшая проверка либо чинится, либо получает **адресное исключение с причиной**.
Ослаблять саму проверку нельзя: мёртвая проверка хуже отсутствующей — она
отчитывается «покрыто». Процедура прогона целиком — скилл `/qa`.

## Публикация

### `publish_release.py`

Собирает дерево ветки `main` — то, что видит и скачивает игрок: `patcher/`
с исходниками и данными, `README.md` витрины, `LICENSE`, а с `--exe` ещё
и `AAI2-RU.exe` через PyInstaller.

```bash
make release                                    # то же самое
.venv/Scripts/python.exe tools/publish_release.py --exe
```

Два места, где он умнее, чем кажется:

* **список модулей вычисляется**, а не выписан руками — разбором импортов
  `patcher/aai2ru.py` вглубь. Забыть модуль нельзя, лишний не попадёт;
* **счётчики в README подставляются из данных перевода**, а размер `.exe` —
  после его сборки. Витрина поэтому не может соврать о том, сколько переведено.

Данные режутся до того, что читает сборка: непереведённые сегменты патчеру
не нужны вовсе, служебные поля тем более. 6,3 МБ превращаются в 3,7.

### `publish_branch.py`

Переносит собранное дерево в ветку `main` и отправляет на GitHub. Работает
во временном worktree, поэтому рабочее дерево `dev` не трогается — публиковать
можно, не прерывая перевод и не пряча незакоммиченное.

```bash
make publish                                    # то же самое, с отправкой
.venv/Scripts/python.exe tools/publish_branch.py          # только коммит
```

**Отказывается публиковать поверх правок, сделанных в ветке руками.** Ветка
генерируется целиком, и правка через веб-интерфейс GitHub была бы стёрта молча
— так уже случалось 12 августа 2026. Свои коммиты инструмент метит строкой
в сообщении и по ней отличает чужие; найдя их, показывает поимённо и требует
либо перенести правку в `release/README.md`, либо `--force`.

### `mk.py`

Мелочи для `Makefile`, которые нельзя доверить шеллу: список целей (`make`)
и уборка (`make clean`). Вынесены сюда потому, что make на Windows исполняет
рецепты через `cmd`, а тот не умеет ни прямых слэшей в пути, ни UTF-8 в `echo`.

### `patcher/` — установщик для чужой машины

Не в `tools/`, но живёт по тем же правилам. `aai2ru.py` — точка входа,
`locate.py` — поиск игры через реестр Steam, `steps.py` — шаги патча,
`selftest.py` — сверка с конвейером репозитория. Своих алгоритмов там нет:
патчер зовёт те же функции `tools/`, нацелив их на чужую игру переменными
окружения `AAI2_GAME`, `AAI2_WORK`, `AAI2_BACKUP`. Разбор — [`release.md`](release.md).
