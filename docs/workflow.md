# Как переводить

> Порядок работы над очередным файлом. Перед началом обязательно открыть
> [`glossary.md`](glossary.md), [`voices.md`](voices.md) и [`decisions.md`](decisions.md) —
> без них будет разнобой с предыдущими итерациями.
> Не влезает текст — [`limits.md`](limits.md). Сломался разбор — [`bytes-format.md`](bytes-format.md).
> Непонятно, чем сделать задачу, — [`tools.md`](tools.md).

## Два конвейера, не один

Реплики и строковые таблицы — разные хранилища и разные инструменты. Улики
в органайзере, имена в плашке говорящего и профили персонажей лежат **не в скриптах**,
и `build.py` их не трогает.

| | Реплики | Строковые таблицы |
|---|---|---|
| Файл | `work/case2.json` | `work/strings.json` |
| Цикл | `extract.py` → правка → `check_len.py` → `build.py` | `extract_strings.py` → правка → `check_strings.py` → `build_strings.py` |

**Всё непереведённое показывается по-английски**, а не по-немецки: содержимое слота
целиком берётся из английской локализации, перевод кладётся поверх.

Вывод инструментов гнать через `PYTHONIOENCODING=utf-8` — иначе кириллица падает
на cp1251, а при перенаправлении в файл ломается молча.

## Цикл итерации

Единица итерации — один файл сценария или небольшая пачка. Порядок — как в прохождении:
`sce1_c0_*` → `sce1_c1_*` → `sce1_c2_*` → `sce1_c3_*`, параллельно логика и предметы
того же участка.

```
1. прочитать glossary.md + voices.md + decisions.md
2. перевести очередной файл в work/case2.json (поле "ru")
3. tools/check_len.py            -> должен быть зелёным
4. спорные места -> спросить пользователя, решение записать в decisions.md
5. git commit
6. периодически: build.py --install и посмотреть в игре
```

Пункт 1 не формальность: именно эти три файла позволяют новой сессии продолжить
с тем же качеством и той же терминологией, не завися от того, что было в контексте.

## Формат work/case2.json

```json
{
  "id": "sce1_c0_01.bytes|01000080|6",
  "file": "sce1_c0_01.bytes",
  "block": "01000080",
  "index": 6,
  "mode": 2,
  "en": "Now, now, Mr. Edgeworth!{E108:0010} I'm sure the guard will\nbring him in any second now.",
  "ru": "",
  "status": "pending"
}
```

- `id` — адрес сегмента: файл, блок, порядковый номер. Не зависит от длины текста,
  поэтому перевод переживает любые правки формулировок.
- `en` — **текстовое ядро** сегмента. Обрамляющие коды (анимации, переходы) сюда не
  попадают и переносятся автоматически, потерять их нельзя.
- `ru` — перевод. Пустая строка означает «не переведено»: такой сегмент останется
  английским, собирать можно на любой стадии.
- `mode` — режим окна из параметра `E107`. Значение `7` — узкое окно, лимит 24 символа.

`extract.py` можно перезапускать: он не затирает уже сделанный перевод, если английский
оригинал сегмента не изменился.

## Разметка управляющих кодов

Коды показаны метками `{E108:0010}`, где `E108` — код, `0010` — параметр (по 4 hex-цифры
на слово). Метки **обязаны сохраниться в переводе** — они несут паузы, интонации,
выделения. `check_len.py` сверяет наборы кодов до и после и валится при расхождении.

Порядок кодов менять можно, набор — нет. Литеральная фигурная скобка в тексте
экранируется удвоением: `{{`.

Часто встречающиеся:

| Код | Что делает |
|---|---|
| `{E108:XXXX}` | Пауза, параметр — длительность. Ставить там же, где ритмически в оригинале |
| `{E107:XXXX}` | Смена режима окна на полуфразе (интонация, говорящий) |
| `{E041}` … `{E040}` | Выделение фрагмента. Оборачивать соответствующие русские слова |
| `{E1D1}` `{E1D2}` `{E1D5}` | Цвет/стиль реплики |

## Геометрия окна

**Две строки, не три.** 50 символов на строку рабочий лимит, 53 жёсткий.
Перенос — обычный `\n` внутри строки перевода.

Расставлять `\n` можно свободно: французская и немецкая версии при том же параметре
`E107` используют другое число переносов, чем английская. Движок к исходной разбивке
не привязан.

Если текст не влезает — **сначала разбить на две строки, и только потом сокращать
формулировку**. Именно так поглощали лишнюю длину немцы: 2 строки в 64,5% реплик
против 51% у англичан. Подробности — [`limits.md`](limits.md).

## Спорные места

Всё, что требует выбора — перевод каламбура, тон конкретной реплики, название улики —
выносится пользователю **до продолжения**, а не копится к концу. Решение записывается
в [`decisions.md`](decisions.md) и становится обязательным для всех дальнейших итераций.

## Кто говорит

Атрибуция реплик — по параметру кода `E101` в преамбуле сегмента:

```bash
.venv\Scripts\python.exe tools\speakers.py            # сводка по всем
.venv\Scripts\python.exe tools\speakers.py --id 0002  # реплики Кей
```

Соответствие идентификаторов персонажам — в [`voices.md`](voices.md).

## Проверка в игре

```bash
.venv\Scripts\python.exe tools\build.py            # черновая сборка в work/build/
.venv\Scripts\python.exe tools\verify_build.py     # проверка бандла
.venv\Scripts\python.exe tools\build.py --install  # установка, ИГРА ДОЛЖНА БЫТЬ ЗАКРЫТА
```

В игре: Options → Language → **Deutsch**. Непереведённые реплики останутся немецкими.

Откат в любой момент: `.venv\Scripts\python.exe tools\restore.py`

**Шрифт ставится один раз, не каждую итерацию.** Две правки `data.unity3d` — коды-носители
и пропорциональные метрики. Они уже стоят; повторять надо только после проверки
целостности файлов в Steam или апдейта игры:

```bash
.venv\Scripts\python.exe tools\patch_font_cmap.py --install
.venv\Scripts\python.exe tools\patch_font_metrics.py --install
```

Проверить, на месте ли они: `restore.py --check` должен показать `data.unity3d` изменённым.
Зачем это всё — [`font-atlas.md`](font-atlas.md).

## Работа несколькими сессиями

Весь контекст перевода лежит на диске: `glossary.md`, `voices.md`, `decisions.md`,
`limits.md` и статусы в `work/case2.json`. Новая сессия читает их и продолжает.

Отдельным проходом полезна **редакторская вычитка свежей сессией** — той, что не
привыкла к собственным формулировкам: она ловит однообразие тона и потерянные шутки.

Разбивать на параллельных агентов имеет смысл там, где пачки файлов независимы.
Согласование голосов и спорные решения остаются в основной сессии — они требуют
пользователя.
